# 血液検査結果OCR取込機能 アイデアメモ（未実装・検討中）

作成日: 2026-08-26。実装前の構想メモ。着手時はこの内容をベースにAskUserQuestionで詰める。

## 目的

動物病院の血液検査結果（紙／写真、手書き混じり）をOCR・AIで解析し、項目名の表記ゆれ（会社ごとの別名）と手書き文字をAIと一緒に確認しながら、健康管理アプリのデータとして取り込みたい。

## 全体フロー（案）

1. 検査結果の写真をアップロード（カメラ撮影 or ファイル選択）
2. 画像をAI（Claude Vision）に送信し、項目名・数値・単位・基準値をJSONで構造化抽出
3. 抽出結果を「項目マスタ」に対して名寄せ（表記ゆれ吸収）
4. 確認UIで複数候補を比較・選択（手書き・低信頼箇所は明示）
5. 確定後、既存データと同じ形でIndexedDBに保存

## OCR/AI解析: Claude Vision API 一本化がおすすめ

専用OCR（Tesseract.js等）＋ルールベース正規化より、手書き文字の判読と項目名の表記ゆれ吸収を同時にこなせる点で有利。プロンプトで「血液検査の写真から項目名・数値・単位を抽出し、手書き部分や自信度の低い箇所にはflagを付けてJSONで返せ」と指示すれば1パスで済む。

代替案比較:

| 案 | 精度/手書き対応 | オフライン | コスト/複雑さ |
|---|---|---|---|
| A: Claude Vision一本化（推奨） | 高い、手書きも強い | 不可（要ネット） | 低〜中 |
| B: Tesseract.js単体 | 低い、手書きほぼ非対応 | 完全オフライン可 | 低 |
| C: Tesseract.js下読み＋Claude補正 | 中〜高 | 不可 | 中〜高（実装複雑） |

## 項目名の表記ゆれ吸収

WBC/白血球数/白血球、ALT/GPT のような別名を束ねる「項目マスタ」を持たせ、AIの抽出結果をこのマスタに対してマッチングさせる。マッチ度が低い・未知の項目はAIに複数候補を出させ、確認UIに回す。

## 確認UI（複数案比較・ユーザー希望）

項目ごとにAIが上位2〜3候補（項目名の解釈違い、数値の読み取り違いなど）を提示し、選択して確定する形。手書き部分は「手書き・自信度低」のバッジを付けて注意を引く。

## 既存アプリとの整合性で要検討の点

このアプリは以下の方針で作られている（`doc/仕様.md`参照）:

- サーバーなし、IndexedDBのみでデータ保存
- Vanilla JS、外部ライブラリ・CDN依存を意図的に排除（オフライン信頼性重視）
- GitHub Pagesで公開

OCR/AI解析にClaude APIを使う場合、この方針とぶつかる点が2つある。

1. **ネット接続が必須になる**: 解析時だけはオンライン前提にする、という割り切りが必要（データ閲覧・入力自体は従来通りオフラインで動く設計を維持）。
2. **APIキーの扱い**: GitHub Pagesは静的ホスティングでサーバーサイドの秘匿ができないため、APIキーをフロントに直接埋め込むとリポジトリが公開の場合は漏洩する。対策は主に3通り。
   - Cloudflare Workers / Vercel Functions等の軽量プロキシを別途1つ用意し、APIキーはそちら側に置く
   - ユーザー本人が自分のAPIキーをアプリのローカル設定画面から都度入力し、ブラウザのIndexedDB/メモリ内だけに留める（コード・リポジトリには一切含めない）
   - リポジトリ自体をprivateにする（GitHub Pagesの制約に注意。有償プラン等が必要な場合あり）

個人利用アプリの規模感なら、「本人がAPIキーを自分で設定画面から入力する」方式が最もシンプルで、既存の「外部ライブラリ・サーバー最小限」という方針にも近い。
