# 猫の健康管理アプリ 仕様書

個人利用向けの猫（DEVICO/でびこ、URICO/うりこ、いずれも腎臓病）の食事・投薬・排泄・体調管理PWA。
サーバーを使わず、ブラウザのIndexedDBだけにデータを保存する。GitHub Pagesで公開し、iPhoneのホーム画面に追加してPWAとして使う想定。

## 1. 技術構成

- Vanilla JS（ESモジュール）。ビルドステップなし。フレームワーク・外部ライブラリ一切なし（オフライン信頼性のため、CDN依存も意図的に避けている。ZIP読み書きも `js/zip.js` に自前実装）。
- データ保存: IndexedDB（`js/db.js` の薄いPromiseラッパー経由）。
- オフライン対応: `service-worker.js` でアプリ本体をキャッシュ（stale-while-revalidate方式）。
- ホスティング: GitHub Pages（`README.md` に手順あり）。

## 2. データモデル（IndexedDB）

DB名 `catHealthDB`、バージョン4。ストア一覧は `js/db.js` の `STORES` 定数を正とする。

| ストア | keyPath | インデックス | 用途 |
|---|---|---|---|
| `codeMaster` | `id`(自動採番) | `byCategoryCode`([category,code]一意), `byCategory` | 各種コード表（後述） |
| `catMaster` | `code` | - | 猫マスタ（DEVICO/URICO） |
| `foodMaster` | `code` | - | 餌マスタ |
| `recipeMaster` | `code` | - | レシピ（複数の餌を混ぜる場合のみ登録） |
| `medicineMaster` | `code` | - | 薬・サプリマスタ |
| `dailyLog` | `id`(自動採番) | `byCatDate`([catCode,date]**一意**), `byCat` | 日ごとの体重/尿量/イベント/メモ/無効フラグ |
| `feedingLog` | `id`(自動採番) | `byCatDate`([catCode,date]), `byCat` | 給餌ログ（1回の給餌ごとに1レコード） |
| `medicineLog` | `id`(自動採番) | `byCatDate`, `byCat` | 投薬ログ |
| `excretionLog` | `id`(自動採番) | `byCatDate`, `byCat` | うんち／ゲロログ（`type`で区別） |
| `memoLog` | `id`(自動採番) | `byCatDate`, `byCat` | 時刻付きメモ |

### codeMaster のカテゴリ

`code: ''` の行は「大分類名称」を表す特別な行（削除不可）。カテゴリ一覧（`dashboard.js` でexportされる定数名）:

- `FOOD_FORM`（餌の形態）, `FOOD_TYPE`（餌の種類）, `MAKER`（メーカー）
- `STOOL_STATE`（うんちの状態、複数選択可）, `VOMIT_STATE`（ゲロの状態、複数選択可）
- `MED_UNIT`（薬の単位）, `MED_EFFECT`（薬の効能）
- `DAILY_EVENT`（日々管理でチェックできるイベント。例: `HOSPITAL`＝通院）

### foodMaster のフィールド

`code, makerCode, name, abbr, caloriePer100g, formCode, typeCode, defaultAmountG, memo, display`

- `display`: **省略時は表示扱い（true相当）**。`false` を明示すると「非表示」＝マスタ画面には出るが、給餌の餌選択には出なくなる（後述「表示/非表示」機能）。
- カロリー入力は `parseCaloriePer100gInput` により `"75/85"`（kcal/内容量g）形式も受け付け、100gあたりに自動換算される。

### recipeMaster のフィールド

`code, name, abbr, components: [{foodCode, ratio}, ...], memo, display`

- 2種類以上の `foodCode` を比率(ratio)付きで登録。単一の餌はレシピ登録不要（給餌側で直接選べる）。
- `display` の意味は foodMaster と同様（非表示にすると給餌のレシピ選択に出ない）。

### medicineMaster のフィールド

`code, name, abbr, kindFlag('DRUG'|'SUPPLEMENT'), defaultDose, unitCode, effectCode, memo, display`

- `kindFlag` 未設定の既存データは起動時に自動で `'DRUG'` へ移行される（`migrateMedicineKindFlag`、1回限りの移行処理）。
- `display` の意味は上と同様（非表示にすると投薬の薬・サプリ選択に出ない）。

### feedingLog のフィールド

`catCode, date, time, kind('INTAKE'|'SERVE'), sourceType('FOOD'|'RECIPE'|null), sourceCode(string|null), providedAmount(number|null), eatenAmount(number|null), breakdown([{foodCode,grams,calorie}]), calorie, memo`

- 「量(g)」の入力欄は種別によって意味が変わる単一フィールド（UI上）。`kind:'INTAKE'`（摂取）のときは餌・レシピ選択と量が必須で、`eatenAmount`に入り、`breakdown`とカロリーが自動計算される。`kind:'SERVE'`（提供）のときは餌・レシピ選択も量も**任意**（未選択・未入力OK）で、`providedAmount`にのみ入る。提供は「参考項目」（食欲を測る補助情報）という位置付けで、カロリー計算には含めない。
- レシピ選択時は `breakdown` に構成餌ごとの按分グラム数・カロリーが入る。

### medicineLog / excretionLog / memoLog

- `medicineLog`: `catCode, date, time, medicineCode, dose, memo`
- `excretionLog`: `catCode, date, time, type('POOP'|'VOMIT'), stateCodes([...]), memo`（`stateCode`単数の旧形式も読み取り時にフォールバック対応）
- `memoLog`: `catCode, date, time, memo`

### dailyLog

`catCode, date, weight, urineAmount, events([...code]), memo, invalid`

- `invalid: true` は「この日は記録なし（データ無効）」トグル。カレンダー上で×印になり、有効データとしてはカウントされない。

## 3. 時刻の特殊表記（重要な内部ルール）

1日の区切りは**朝6:00始まり**。以下は `js/utils.js` に実装。

- **通常時刻**: `"HH:MM"`（00〜23時）。
- **延長時刻表記**（日をまたいだ深夜の記録）: 実時刻0:00〜5:59台の記録は、その日の続きとして扱うため `+24` した表記で保存する（例: 深夜1:20 → `"25:20"`）。これによりソート順（文字列比較）が正しく保たれる。表示時は `formatDisplayTime()` が自動的に24を引いて通常表記に戻す。
- **夜間（時刻不明）**: `"99:00"` 固定の擬似時刻。就寝中などで正確な時刻が分からない記録用。その日の最後にソートされ、表示は「夜間」という文字列になる（`formatDisplayTime()`が変換）。全4つの記録フォーム（給餌/投薬/排泄/メモ）に「夜間（時刻不明）」チェックボックスがあり、チェックすると時刻入力欄が無効化されて自動的に `99:00` で保存される。

### 関連ユーティリティ（`js/utils.js`）

- `logicalTodayStr()`: 実時刻が0:00〜5:59なら前日の日付を返す（「論理上の今日」）。カレンダーの「今日」ハイライトや初期表示日、「今日に戻る」ボタンの遷移先に使用。
- `normalizeEntryTime(timeStr)`: フォームで入力された `"HH:MM"`（0〜23時）を、0〜5時なら+24して延長表記に変換。**保存時**に全フォームで適用。
- `formatDisplayTime(timeStr)`: 内部表記→表示用に変換（延長時刻を戻す／`99:xx`以降を「夜間」に変換）。**表示時**に使用。
- `floorToTenMinutes(timeStr)`: 分を10分単位に切り捨て（例: `10:11`→`10:10`）。時刻入力欄の`change`イベントで常に適用。
- `quickTimeHourOptions()` / `quickTimeMinuteOptions()` / `nearestQuickTime()`: クイック選択プルダウン用（後述）。

## 4. 画面構成

### 4.1 タブバー（`app.js`）

「設定」タブ＋猫ごとのタブ（`catMaster` の内容から動的生成）。

### 4.2 設定タブ（`dashboard.js`）— サブタブ

絵文字アイコンで6つ切り替え: 🍽️餌マスタ／📖レシピ／💊薬・サプリマスタ／🏷️コードマスタ／🐱猫マスタ／📁データ入出力

- **餌マスタ・レシピ・薬マスタ共通の機能**:
  - 検索・フィルタ（餌マスタはメーカー/形態/種類/表示非表示、レシピと薬マスタは表示非表示のみのフィルタ）
  - 各カードに「非表示にする」/「表示に戻す」ボタン（1クリックで`display`フラグ切替、即保存）
  - 非表示のカードは半透明表示＋「非表示」バッジが付くが、**マスタ画面には常に全件表示**される（除外されるのは給餌・投薬時の選択肢のみ）
  - 編集は✎ボタン、削除は🗑️ボタン（使用中のデータがある場合は削除不可のガードあり）
- **コードマスタ**: 大分類（アコーディオン）ごとにコード一覧。追加・編集・削除可能（使用中コードは削除不可）。
- **猫マスタ**: 猫の追加・編集・削除（記録が既にある猫は削除不可）。
- **📁データ入出力**:
  - エクスポート: ストアごとのチェックボックス（デフォルト全選択）→ZIPファイルとして書き出し。`navigator.share`が使える環境（主にスマホ）ではOS共有シート経由（Google Driveアプリへの直接保存等が可能）、使えない環境は従来のダウンロードリンクにフォールバック。
  - インポート: ZIP・JSONどちらも対応（拡張子/MIMEで自動判別）。ファイルに含まれるストアのみ上書き。
  - 猫別・日々データ取込: `import/devico.json` 形式のJSONを取込（`dayImport.js`）。対象の猫×日付だけを作り直すので他データに影響なし。重複しない。
  - 初期化: 全データ削除→`initial-data.js`の内容で再構築（元に戻せない）。

### 4.3 猫タブ（`catTab.js`）

アイコンナビで6セクション切替: 🍴給餌管理／💊サプリ・投薬管理／💩うんち記録／🤮ゲロ記録／📝メモ／🏥日々管理。上部に日付バー（＜／日付表示／＞／今日に戻る）、下部にカレンダー。

**全フォーム共通の入力パーツ**（`buildDateFieldHtml` / `buildTimeFieldHtml` / `wireTimeField` として共通化）:

- **日付欄**: `<input type="date">`。デフォルトは表示中の日付（編集時はそのレコードの日付）。**別の日付を選んで保存すると、保存後に自動でカレンダー表示・日付バーもその日付に切り替わる**（ヘッダー含め画面全体を再描画）。
- **時刻欄**: ネイティブの `<input type="time" step="600">`（手入力・タップ選択どちらも可）＋隣にクイック選択プルダウン（時: `06,07...23,24,01...05` の順／分: `00,10,20,30,40,50`）。クイック選択を変更すると時刻欄に反映される（一方向。時刻欄を直接編集してもクイック選択側は追従しない）。初期値は現在時刻に一番近い値（新規時）または編集対象の時刻（編集時）。「夜間（時刻不明）」チェックを入れると時刻欄とクイック選択が両方disabledになり、保存時は`99:00`になる。
- 保存時、分は常に10分単位に切り捨てられる。

**🍴給餌管理**:
- 種別（摂取／提供）＋日付＋時刻＋メーカー/形態/種類フィルタ＋検索＋餌・レシピ選択＋量(g)＋メモ。
- 摂取(INTAKE): 餌・レシピ選択と量が必須。カロリー・按分は自動計算。
- 提供(SERVE): 餌・レシピ選択・量とも任意（未選択/空欄OK）。カロリーには含めない。
- 一覧テーブルに「種別」列は無い。提供(SERVE)の行は行全体がグレー背景（`tr.serve-row`）で摂取と視覚的に区別する。
- 編集✎／削除🗑️ボタン。非表示(display:false)の餌・レシピは選択肢から除外されるが、編集中エントリで既に選ばれているものは選択が消えないよう表示され続ける。
- 直近の選択は猫ごとに`localStorage`（`catHealth:lastFeedSelection:<catCode>`）に記憶し、次回のデフォルト候補にする。

**💊サプリ・投薬管理**: 日付・時刻・薬/サプリ絞り込み＋名前検索・薬・サプリ選択・用量（選択した薬のデフォルト用量/単位が自動反映）・メモ。編集✎／削除🗑️。非表示の薬は選択肢から除外（編集中の選択は維持）。

**💩うんち記録／🤮ゲロ記録**: 日付・時刻・状態（複数選択チェックボックス、コードマスタの`STOOL_STATE`/`VOMIT_STATE`）・メモ。削除🗑️のみ（編集機能なし）。

**📝メモ**: 日付・時刻・メモ本文。削除🗑️のみ（編集機能なし）。

**🏥日々管理**:
- 「この日は記録なし（データ無効）にする」トグル（即時保存、日付欄とは独立して常に**表示中の日**に対して効く）。
- 日付・体重(kg)・尿量(ml)・イベント（複数選択）・メモ→保存ボタン。日付を変えて保存すると他フォーム同様その日付にカレンダーが切り替わる。
- サマリー行: `🏥 体重Xkg 尿量Xml 合計🔥Xkcal イベント名...`（🔥合計カロリーはその日の`feedingLog`のうち`kind:'INTAKE'`のみ合算）。
- 集約ログ: その日の🍴給餌（**摂取のみ。提供ログは表示しない**、種別ラベルも表示しない）／💊投薬／💩💩🤮排泄／📝メモを時刻順にまとめて一覧表示。

**カレンダー**: 月表示。記録がある日はドット、無効日は×、選択中の日はハイライト、論理上の今日には枠線。日付タップで表示日を切り替え。

## 5. 猫別・日次ログ取込フォーマット（`import/FORMAT.md`）

`devico.json` / `urico.json` のような、1猫分の日々の記録を日付ごとにまとめたJSON。詳細は `import/FORMAT.md` を参照。要点:

- `{ catCode, days: { "YYYY-MM-DD": {...} } }` 構造。
- 1日分は `weight, urineAmount, events, memo, invalid, feeding[], medicine[], poop[], vomit[], memos[]` を必要な項目だけ書けばよい。
- 取込は「猫コード×日付」単位で該当日をまるごと作り直す（他の猫・他の日・マスタには影響しない）。何度取り込み直しても重複しない。
- `feeding`要素の`time`は上記「延長時刻」「99:00」ルールに従う。

## 6. バックアップ（ZIP）

`js/zip.js` が依存ライブラリなしでZIPの読み書きを実装。

- 書き込み: STORE方式（無圧縮）のみ。
- 読み込み: STORE方式に加え、`DecompressionStream('deflate-raw')`が使える環境ではDEFLATE方式（OS標準の圧縮フォルダ機能等で固め直されたzip）も許容。
- `js/io.js`: `exportSelected(storeNames)`でストアごとの`.json`＋`meta.json`をまとめてZIP化。可能なら`navigator.share`（共有シート）、不可なら`<a download>`でダウンロード。`importAll(file)`はファイル名/MIMEでZIP/JSONを自動判別し、含まれるストアのみ`clearStore`→`put`で置き換える。

## 7. 起動時の初期データ投入（`seedDefaults`, `dashboard.js`）

`initial-data.js`の内容のうち「まだ登録されていないコード/データ」だけを自動追加する（`ensureXxx`系関数、`code`重複チェック）。**既にアプリ内で編集・削除したデータは上書きされない**。ユーザーは`initial-data.js`を直接テキスト編集して追記していく運用（コード内にコメントで書き方の説明あり）。

## 8. PWA・オフライン・更新の仕組み

- `service-worker.js`: `CACHE_NAME`（現在`cat-health-cache-v2`）でバージョン管理。`install`時に主要ファイルをプリキャッシュし`skipWaiting()`、`activate`時に古いキャッシュを削除し`clients.claim()`。`fetch`はキャッシュ優先＋バックグラウンドで再検証（stale-while-revalidate）。
- ヘッダーの「🔄更新」ボタン（`app.js`の`forceUpdate()`）: Cache Storageを全削除→Service Worker登録解除→`location.reload()`。**IndexedDB（データ本体）には触れないため、更新してもデータは消えない**。JS更新が反映されにくい問題への対策として追加。
- 通常のPWA更新検知（`CACHE_NAME`を変えて`service-worker.js`自体のバイト列が変わる）は効くが、iOS Safari等では検知が遅いことがあるため上記の手動更新ボタンが実質的な主手段。

## 9. テスト方法（開発時）

ビルドツールなしのため、Node + jsdom + fake-indexeddbで動作確認する運用。

```
npm i -D jsdom fake-indexeddb   # 初回のみ、作業用ディレクトリで
```

- リポジトリを一時ディレクトリにコピーし、jsdomで`document`/`window`をグローバルに用意、`fake-indexeddb/auto`をimportしてIndexedDBを模擬。
- `renderCatTab` / `renderDashboard` 等を呼び出しDOM操作をシミュレートし、`window`の`error`イベントでJSエラー0件を確認してから完了報告する。
- 主要フローの回帰テストスクリプトを都度用意（過去のセッションでは`run_test2.mjs`という名前で使い回していた）。
